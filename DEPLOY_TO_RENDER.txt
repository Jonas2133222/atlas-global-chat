ATLAS — RENDER DEPLOY INSTRUCTIONS

1. Extract ATLAS_RENDER_READY.zip. You should see server.js, package.json,
   render.yaml, and ATLAS Global.html directly in the extracted folder.
2. Create a new GitHub repository (e.g., atlas-global-chat).
3. On GitHub, choose "uploading an existing file" / Add file > Upload files.
   Open the extracted ATLAS_RENDER_READY folder, select ALL its contents
   (including the tests folder), and upload them to the ROOT of the repository.
   Do NOT upload the ZIP file itself, and do NOT just upload the HTML file.
   Commit the files. If your OS hides .gitignore, that is fine.
4. Visit dashboard.render.com > New > Web Service.
   Connect GitHub, select your repository, and select Language: Node.
   If entering commands manually, use:
     Root Directory: [leave blank]
     Build Command: npm install
     Start Command: node server.js
     Instance type: Free
     Health Check Path (optional): /api/health
   Render provides PORT. You do not need to set a port yourself.
5. Click Create Web Service and wait until Render says Live.
   Your website will be at https://<your-service-name>.onrender.com
6. Check https://<your-service-name>.onrender.com/api/health
   It should respond with {"ok":true,"chat":"live","cooldownMs":1000}.
7. Open the main website in two devices/browsers, choose nicknames,
   enter the SAME chat room, and send a test message.

ALTERNATIVE: New > Blueprint and connect the same repo. This copy includes
render.yaml with Node, Free, npm install, node server.js, and the health check.

IMPORTANT:
- Choose WEB SERVICE, NOT Static Site, because the chat requires Node.
- Do not open ATLAS Global.html alone from GitHub Pages: chat won't work.
- The local Windows launcher scripts are not used by Render.
- A free Render web service spins down after about 15 minutes without inbound
  traffic; it can take around a minute to restart when someone visits.
- Chat history and reports are stored in local files. These WILL BE LOST when
  free Render instances restart, redeploy, or spin down. A permanent database
  is required for persistent public message history.
- Built-in slur filtering can miss disguised hateful speech. Reporting is
  logged, but no separate human moderation dashboard is included.
- The free tier has shared monthly resource limits; check Render dashboard.
